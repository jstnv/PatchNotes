IMPLEMENTED BEHAVIOR

Whitespace-only names and invalid catalog selections are rejected without state
mutation. Valid setup needs no cash reserve. Stale duplicate callbacks are rejected.
Preparation and existing financial-boundary checks precede the one run-cycle commit.
The action can earn/settle existing historical sales through the existing boundary;
it has no purchase charge. Integer-overflow rejection remains atomic.
New project cycle is 0; the first completed Design hand advances it to 1.

Western, Post-Apocalyptic, Mystery. Themes are identity data only.
No Theme cards, compatibility, market modifiers, Review effects or Genre Fit
calculation were introduced. Existing Review arithmetic is unchanged.

A new ProjectState resets core scores, accumulated Scope, Bugs, bug pressure,
Awareness, production priorities, implemented/exhausted Feature history, finalization
results and phase-local selections/candidates. Existing required Scope remains 30.
New concealed market snapshots are assigned through existing initialization.
Design redraws refresh to exactly 4; the HUD binds the new project without redesign.
Eligible Feature supply is copied from RunState ownership and filtered through the
authoritative CardDatabase phase boundary; no second starting roster was added.
The project supply is fixed at creation. Design and Alpha use the existing shared
project-supply path. Later purchases belong to future projects.

The same RunState is retained: exact-cent cash, advanced calendar, Feature ownership,
familiarity, prerequisite-play credits, release metadata and historical sales.
Existing multi-release earning/settlement remains unchanged.
Employees, courses and publisher relationships have no implemented runtime fields
in this repository; no parallel placeholder progression systems were invented.
Retaining the same RunState preserves other existing explicitly run-owned fields.

Duplicate base names are accepted before release. ProjectState stores base identity;
RunState release metadata and sales records separately store base_name, release_title
and actual release_year. The first released name is plain; later occurrences append
the actual launch year, including projects created in an earlier year. Titles remain
permanent after later releases and reconstruction. Same-year duplicates may have
identical display titles; stable project IDs distinguish their records.
Repeated registration of the same identity is idempotent; conflicting identity
under an existing ID is rejected.

Launch commits existing results and enters Studio directly at zero cost.
The existing five-tab review is accessible from Summary > Detailed Review and
returns to Summary freely. It no longer gates Studio entry. Studio Feature Store,
summary, contract navigation and normal HUD remain integrated.
