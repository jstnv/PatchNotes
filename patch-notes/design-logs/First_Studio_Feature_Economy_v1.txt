FIRST STUDIO AND OWNERSHIP
Creating a named Studio through the main menu activates this economy in RunState. The run receives $5,500.00 and owns only Text, 4-Color Palette, 8-Bit Sound, Keyboard & Mouse, Controller, and Controls at no acquisition charge. Their printed ledger Scope totals 7. A full-screen first-Studio selection gates first-game setup. Optional Primitive Features cost $300.00 for 1 Scope, $450.00 for 2 Scope, or $600.00 for 3 Scope. Initial optional spending may not exceed $4,000.00, and total owned starting-pool printed Scope may not exceed 23. Initial selection spends exact-cent cash, costs zero cycles, and can commit only once. A selection below 20 Scope presents an explicit confirmation warning and may proceed if accepted. There is no per-phase minimum. Unspent cash remains in RunState for production.

UNCHOSEN FEATURES AND BRANCHES
Unchosen Primitive Features remain in the Studio Feature Store at the same Scope-based reserve prices. Each later reserve purchase validates ownership and affordability, then spends exact cash and advances one central productive run cycle. Ownership is permanent for the run; the next project's eligible Feature supply is derived from that ownership. A purchased parent immediately unlocks its existing Feature Store child. Feature exhaustion remains independent and finite within each project. Existing later-era Feature Store prices and zero-cycle purchase rules are unchanged. A pending initial selection cannot be bypassed through the Feature Store or next-project path.

PRINTED FEATURE PLAY COST
For each Primitive Design or Alpha Feature in a successfully resolved four-card hand, cost in cents is 1,000 × (printed primary Core value + printed secondary Core value + 2 × printed Scope). Sum the whole selected hand before production; Core Passes cost zero. The UI shows the selected hand's cost and disables an unaffordable Implement button. The action handler preflights again, so an unaffordable hand preserves cash, Scope, Core Scores, exhaustion, project/run cycles, redraws, and sales. The central productive-action boundary commits the direct production and negative cash delta together, advances one cycle, restores redraws, then settles sales. No cost applies to mere drawing/selection or a failed action. Contracts and later Feature classes are excluded because their play-price rules are not locked.

COMPATIBILITY AND RECONSTRUCTION
New main-menu named-Studio runs activate the economy. Directly injected legacy RunState fixtures without Studio creation retain their existing all-Primitive, zero-starting-cash behavior, preserving established phase and contract regressions; this is a compatibility boundary, not a second new-game rule. RunState owns cash and Feature ownership, ProjectState snapshots eligible supply when a new project begins, and Studio/phase replacement reuses the same RunState. No save/load migration is implemented; that remains release-critical work.
