IMPLEMENTED FLOW
After studio naming, the dashboard is usable immediately. A small inline TIP beside the Feature Store button and the button tooltip recommend buying Primitive Features before the first game. The hint shows current printed Scope and initial purchase spending. It is a normal part of the Studio dashboard, not a blocking selection menu. Opening and closing the store cost zero cash and cycles.

The Feature Store lists unowned Primitive Features as first-game starters while the initial purchase window is open. A single click on Purchase Starter Feature buys the selected node; the player can select and buy another node normally. Each purchase spends exact cents immediately, grants permanent RunState ownership, updates the hint and tree, and costs zero cycles. The existing $300/$450/$600 Scope prices, $4,000 combined initial spending cap, and 23 printed Scope cap apply across these sequential purchases. Duplicate, unaffordable, or cap-exceeding attempts leave cash, ownership, calendar, redraws, and store state unchanged. Later-generation store nodes remain visible but cannot be purchased during the starter window; they become available after the first project begins. A purchased Primitive parent reveals its Feature Store branch.

Clicking Produce First Game with fewer than 20 printed Scope shows a warning; dismissing it leaves the starter window open. Accepting it opens Pre-Development without spending or closing that window. Cancelling Pre-Development also leaves purchases available. The starter window closes only after the first project's existing productive-cycle transaction succeeds, so a failed project start does not lock the player out. After that boundary, unchosen Primitive Features remain reserve purchases at the same prices and one cycle each. Initial purchases still have no minimum count by phase.

OWNERSHIP AND PRESERVED RULES
RunState owns funding, permanent Feature ownership, cumulative initial spending, and the first-project boundary. StudioPhase owns the inline hint and warning presentation; FeatureStore owns browsing and purchase controls. Gameplay keeps the same RunState across phases and snapshots owned Features into the new ProjectState supply. Primitive Design/Alpha play costs, Feature familiarity, contract economics, release history, sales settlement, and later Feature prices are unchanged. The former StarterFeatureSelection screen and its UID were removed.
