## Actual review and card mechanics

The current review path clamps each Core/standard ratio to 1.25, averages four ratios, subtracts half their population standard deviation, multiplies by 8 and caps production rating at 10. It then multiplies by `min(actual Scope / required Scope, 1)` and `max(0.25, 1 - remaining bugs / required Scope)`, adds a variance from {-0.50, -0.25, 0, +0.25, +0.50}, caps to [0,10], and rounds half-up to one decimal (`scripts/review/primitive_review_calculator.gd:55-103`). Genre Fit is embedded in the four standards; the legacy accessor returns a neutral 1.0. Current Market can freeze standards up to +8 over base Action values, so a campaign run must retain its actual market snapshot.

An exact optimistic Scope bound under the actual required Scope of 30 follows: even with production rating 10, zero remaining Bugs and the best +0.50 variance, a displayed 8.0 needs `10 * actual_scope / 30 + 0.50 >= 7.95`, or at least 23 actual Scope. This is only a necessary bound, not a reachable-route proof. The earlier 35-required-Scope calculation was inapplicable.

The authoritative card loader combines `data/card_ledger.json` and `data/feature_store_ledger.json`; future supply filters retired IDs and parent replacements (`scripts/cards/card_database.gd`, `scripts/cards/feature_store_catalog.gd`). Printed Feature Core must use `CardData.core_contributions()` / `printed_core_total()`, including ordered three-contribution cards; summing only legacy primary and secondary fields would undercount some current cards. Design and Alpha use the same four renewable value-2, zero-Scope Core Pass definitions. Selected finite Features exhaust; unselected cards remain in the candidate fan. Design and Alpha each draw up to seven candidates, choose four to play, and replenish played slots. Presently their deal functions repeatedly sample renewable Pass definitions with no budget (`scripts/simulation/design_hand_command.gd:193-235`; `alpha_hand_command.gd:206-230`). Weighted selection is priority times each printed contribution (`scripts/phases/weighted_candidate_math.gd`). Redraw uses a separate class split when both Features and Passes are available (`scripts/simulation/development_actions.gd:282-335`); it does not consume a production cycle. The existing hand validation and some employee actions assume exactly seven candidates (`development_actions.gd:82,236`; Design/Alpha command paths). These must be accounted for when fewer candidates become legal.

Both phases form production from printed Core. Four cards sharing a primary category trigger 1.5x specialization; otherwise an eligible mixed hand can redistribute a 1.25x total across four categories (`scripts/simulation/production_hand.gd`). Design Feature bug pressure is `printed_core_total * Scope / 18`; Alpha has its own analogous pressure (`design_hand_command.gd:296-298`, `alpha_hand_command.gd:335-337`). Finalization and Beta QA alter remaining bugs. Passes add Core without Scope or Feature bug pressure, so a budget must be evaluated against Scope completion and bug cleanup together.
