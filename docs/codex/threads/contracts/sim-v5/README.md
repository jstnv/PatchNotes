To reconstruct the exact project, check out that HEAD into a **disposable** directory, apply the overlay ZIP at the project root (`patch-notes/`), and verify every project-file SHA-256 against the manifest. Copy [promotion_balance_v5.gd](promotion_balance_v5.gd) to that disposable project's `scripts/debug/` directory. Import with Godot 4.7.1 headless, then run `--script res://scripts/debug/promotion_balance_v5.gd -- --cohort=neon-current --out=<absolute-output-path>` and repeat for `neon-lease` and `crown-lease`. Use isolated APPDATA/LOCALAPPDATA and a distinct `PN_CHECKPOINT_TEST_PORT` as in [run.py](run.py). The original run used `C:\Users\64jus\Downloads\Godot_v4.7.1-stable_win64.exe\Godot_v4.7.1-stable_win64_console.exe` and [exact command records](neon-current.command.json).

The three full JSON traces are in [native-traces.zip](native-traces.zip). [audit.py](audit.py) reads the ZIP, checks matched states, Contract hands, native card choices, launch timing, award consumption, settlement endpoints, finance validity and the archived dirty overlay, then regenerates [audit-summary.json](audit-summary.json). [audit-summary-at-run.json](audit-summary-at-run.json) retains the all-file copy hash check from before temporary cleanup. Import and cohort logs remain alongside the command records. `pack.py` and `archive_source_overlay.py` describe the archive verification steps used before cleanup.

The cash-only arm removes the target award in analysis memory after the same legal Contract. This is an isolation device, not a player action. The no-offer arm skips the target Contract and launches two cycles earlier; it is an opportunity-cost context only. Do not infer a final numerical approval from these deterministic routes.
