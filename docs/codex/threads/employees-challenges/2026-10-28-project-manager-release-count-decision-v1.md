# Project Manager qualifying games count on release — 2026-10-28

**LOCKED design timing; NOT IMPLEMENTED:** A game contributes **one** of the [four distinct games required for a Project Manager course level](2026-10-28-project-manager-four-games-decision-v1.md) only when that game is successfully released after achieving two actual qualifying Specializations. Those Specializations may hit different categories; at each trigger, its category must be at the [lowest legal priority percentage](2026-10-28-project-manager-minimum-priority-decision-v1.md) for that screen and trained level. The same released game cannot contribute more than one of the four, even if it has more qualifying Specializations. An abandoned or unreleased project, a rejected release and a duplicate callback add no game progress. The user chose release-time credit specifically to prevent course exploits.

Buying the course only [unlocks its challenge tracker](2026-10-28-course-unlocks-challenge-decision-v1.md). A fourth qualifying release completes that course's challenge and grants its range benefit through the normal employee challenge-completion rule. Whether Specializations earlier in a project but before course purchase count, eligible phases/Contract hands, whether two events in one hand count and exact save/receipt identity remain OPEN. Do not retroactively count historical releases by inference.

The proposed 20%–40% four-category and 40%–60% two-category Beta starting ranges remain trial design values. No gameplay, slider, save, rival or shared TODO change follows from this note.
