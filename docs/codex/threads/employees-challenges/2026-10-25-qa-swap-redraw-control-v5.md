# QA swap through the Beta Redraw control — 2026-10-25, version 5

## User-selected interaction

**LOCKED design, NOT IMPLEMENTED:** The trained and project-armed QA swap uses the existing Beta **Redraw** button, which displays **Swap** when exactly one eligible Search or Debug card is selected. It does not add a separate button or consume a redraw. The action is available even when no ordinary redraws remain. Swap **turns the selected card into the opposite Search or Debug card while keeping its value and hand slot**. It does not draw from the Beta pool. From that point, the card is the opposite card for display, Beta resolution and hand qualifications, **including pure-hand counting**; its former operation does not secretly count. A successfully used swap spends the project's one armed use; a canceled, rejected or duplicate action does not. The [training and arming rule](2026-10-25-qa-two-challenges-decision-v4.md) still requires three committed pure Search and three pure Debug hands across projects, followed by a *new* pure hand in each project to arm one later-hand swap.

When **multiple cards** are selected, the button remains **Redraw** and follows the existing ordinary multi-card redraw rules, including the redraw budget. This does not spend the armed QA swap. When the single selected card is not an eligible QA Search/Debug card, the employee is untrained, the project is unarmed, or the use is spent, ordinary Redraw remains available under its normal rules. Swap is a Beta hand-planning action before committing the later hand; it adds no productive cycle, card slot, free Bug discovery/fix or Core score.

**LOCKED classification clarification:** The user's “just be the opposite card” means a committed hand is classified by the card **after** Swap. Four effective Search cards count as a pure Search hand; four effective Debug cards count as a pure Debug hand. The mixed-hand challenge still requires actual Search discovery and Debug fixing. This classification does not retroactively alter earlier committed hands. Multiple trained QA employees and the persistent representation of the changed card remain **OPEN**. The selected swap adds no random draw or new card value.

## Current-source boundary

The current Beta UI has one `RedrawButton`; its press handler calls `redraw_selected_cards()`. That path replaces every selected candidate, checks enough redraws for the selection size, and charges one redraw per card. The new Swap state therefore needs its own validated action branch and display state. It must not call the ordinary redraw transaction and then merely refund the budget, which would still draw a replacement card. Source inspected: `patch-notes/scripts/phases/beta_phase.gd` and `patch-notes/scripts/simulation/development_actions.gd`. This is design guidance, not code approval or an implemented behavior claim.
