**USER-SELECTED UI rule; NOT IMPLEMENTED OR QUEUED.** After Production course 2's challenge is complete, selecting exactly **one eligible visible Core Pass** in Design or Alpha and pressing the existing **Redraw** control opens a choice menu. It lists the existing Core Pass definitions whose printed primary matches a visible Feature's printed primary or secondary Core and differs from the selected Pass. The menu also offers **ordinary redraw**. No new persistent Align button is needed. Selecting multiple cards, a single Feature, or a Pass with no eligible matching alternative follows ordinary redraw behavior. Alpha's playtest-injected protected Passes remain ineligible for either replacement or ordinary redraw under their current rule.

Confirming one chosen Pass replaces only that selected candidate slot with the chosen actual Pass definition and spends **one normal redraw**. It uses no productive cycle, creates no extra card or Feature, and does not grant immediate Core score. Confirming ordinary redraw invokes the unchanged random replacement path and its normal cost. Canceling, closing, stale choice, zero redraws, invalid target or failed save/transaction preflight changes no card, redraw count, RNG or training state. Multiple selected cards never enter this menu and keep ordinary multi-card redraw costs. The chosen replacement is repeatable while redraws remain, with no separate project cap.

The source fan uses candidate-token identity; duplicate renewable Pass definitions may appear in different slots. The implementation must bind the selected token, visible Feature and chosen Pass ID to one valid atomic command, show its exact post-choice card before confirmation, and preserve deterministic replay/Continue. A chosen deterministic replacement need not sample the deal RNG; ordinary redraw still follows its existing RNG rules. These identity/preview details are proposed implementation requirements derived from the selected action, not evidence of a current feature.
