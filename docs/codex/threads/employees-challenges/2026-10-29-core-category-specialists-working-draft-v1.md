# Core-category Specialists (G/S/T/D) — working design draft, 2026-10-29

**DESIGN IN PROGRESS; NOT IMPLEMENTED OR QUEUED.** This draft captures the user's five-course direction for one specialist in each Core category: Graphics, Sound, Technology and Design. These are employee roles, separate from a Studio's founding Genre specialty and from the existing Production Specialist. The four roles use the same rules with a different owned category. Their purpose is to reward deliberate Specialization play, diversify hand building and eventually let a strong Studio shape rivals' Genre standards. [Later ruling](2026-10-29-core-category-course-economics-decision-v1.md) selects standard **trial** tuition and challenge-earned raises; course names, hire timing, first payday and several integration rules remain **OPEN**. No shared TODO contribution follows from this draft.

## Current baseline and selected design choices

- A Design/Alpha Specialization is one committed four-card hand whose **four printed primary Core labels match**. Features and Passes both qualify. Current `ProductionHand` applies **×1.5 to every Core score in that hand**, rounded separately by Core category; secondary Core gains are included, while printed Scope is unchanged. Features are finite within the project; Core Passes renew. Beta's QA/Marketing Specializations are different systems.
- **USER-SELECTED on-hire benefit:** each G/S/T/D specialist gives **+0.05 to the multiplier of their own category's Design/Alpha Specialization**, with no course purchase. Trial arithmetic is ×1.50 → ×1.55 for that category's matching hand; a trained +0.10 course would make it ×1.65 if increments are additive. This affects the whole qualifying hand's Core gains under today's resolver, not only primary-category points. A non-Specialization hand receives no benefit. The alternative +1 primary score on every matching Feature was set aside because it also boosts ordinary hands and is amplified by synergy.
- **USER-SELECTED standard scope:** the future +2 Genre/Core standard pressure applies to **rivals' future projects only**, never to the player's own Review target. Each later player release **above 8.0 Review** with the specialist's category still dominant adds **another +2** for that Genre and category, up to **+8 specialist lift**. Existing projects and released Reviews remain frozen.
- **USER-SELECTED retrigger scope:** an extra Specialization hit repeats only its **Core bonus**. It does not replay base card output, Scope, Bug pressure, card exhaustion, familiarity, cash, a cycle or the hand itself. QA's Feature replay search interaction with extra hits remains OPEN.
- **USER-SELECTED dominance test:** the specialist's category is dominant when its **final released Core score is highest** among the four categories; ties for highest count. Use that same test for the three training releases and every later >8.0 standard-setting release.
- **USER-SELECTED course structure:** the five courses form a **sequential ladder**. A later course becomes purchasable only after the prior course's challenge is complete. As with other employee courses, buying a level starts its tracker and grants no immediate course buff.
- **USER-SELECTED course economics:** each course costs **$150** and adds **$100/month prospectively only after its challenge completes**, on the existing $1,000/month employee base trial. Five completions yield **$1,500/month** for that employee. These are trial terms, not final balance; [dated economics decision](2026-10-29-core-category-course-economics-decision-v1.md).
- **USER-SELECTED release counting:** courses 1, 3 and 4 credit a game only on successful release. Course 1 needs **four** category Specializations in **each of four** released games; course 3 needs **two pure-Feature** category Specializations in **each of two** released games; course 4 needs **three pure-Pass** category Specializations in **each of three** released games. Distinct released games count once per course.
- **USER-SELECTED Feature Boost effect:** the +1 affects the **selected Feature card's primary Core score on its next play only**; its secondary score and Scope stay unchanged. The Feature's permanent definition and future-game copies do not change.
- **USER-SELECTED Pass Conversion target:** an armed conversion lets the player **choose one eligible, already-owned Feature** with the specialist's printed primary Core category. It is not a random draw or a new Store grant.
- **USER-SELECTED Pass Conversion control:** while the reward is armed and exactly one ordinary Pass is selected, **Convert replaces the existing Redraw button**, analogous to QA's one-card Swap. Convert takes priority over Production Pass Alignment for that selection. Once the phase's conversion is used, Alignment becomes available again through its normal one-Pass Redraw choice.
- **USER-SELECTED free phase actions:** after its course is trained and the matching pure-hand Specialization arms it, **Boost and Pass Conversion each allow at most one use per Design phase and one per Alpha phase**. The use costs no redraw, cash or productive cycle. The arming hand cannot use the newly armed action.
- **USER-SELECTED retrigger trial:** each qualifying outside-category Specialization adds **5 percentage points** to the employee's chance, capped at **50%**. Save that hand's chance before the four selected cards score left to right. **Each card rolls independently at the saved chance**, so an early hit does not suppress later cards in the same hand. A successful card can chain with each next roll at half the previous chance, up to **three extra Core-bonus hits for that card**. If any card retriggers, reset persistent buildup after the hand; otherwise it **carries across games**. These are trial values and selected timing rules, not a balance finding.
- **USER-SELECTED simultaneous specialists:** if several trained category specialists qualify on one outside-category Specialization, each advances and rolls its **own** chance independently. A hit resets only that specialist's buildup. Exact deterministic roll order and combined rounding are implementation design.
- **USER-SELECTED Market composition:** the specialist's capped +8 rival-only Genre/category lift **adds on top of** the existing Market density/strong-release lift. Current source validates only the older bounded lift, so the future implementation needs an explicit versioned target/schema change. Previously frozen rival/player projects and released Reviews stay unchanged.

A hand counts only on a successful committed Design/Alpha action, with printed primary labels and actual card classes, once by unique project/action identity. Distinct successful releases are required for all five courses; abandoned or duplicate release events do not advance them. Training hands never use the benefit they unlock. The $150 tuition and prospective +$100/month challenge raise are **user-selected trial terms** for these four roles, on the established $1,000 employee base. ## Benefit mechanics needing a ruling

1. **Feature Boost:** The selected +1 goes to the selected eligible Feature's primary Core value on its next play only; secondary Core and Scope are unchanged, and the global card definition is not mutated. Keeping Bug pressure tied to printed base values is a **candidate**. The Boost action costs no redraw, cash or cycle and is usable at most once per phase after a qualifying arming hand. The arming hand cannot boost itself. Reject stale, exhausted, unowned and protected-card targets without consuming the arm. The source's raw score and synergy rounding must establish the exact application point.
2. **Pass Conversion:** The player chooses one currently owned, legal, unexhausted Feature of the specialist's printed primary category to replace one ordinary visible Pass. It changes one fan slot and preserves a finite Feature's normal exhaustion when eventually played; it never grants Store ownership. The conversion costs no redraw, cash or cycle and is usable at most once per phase after a qualifying arming hand. Alpha's injected protected playtest Passes should stay protected, and the chosen finite Feature must not duplicate an already visible instance. The user selected **Convert replacing Redraw** for exactly one selected Pass while armed and taking priority over Production Pass Alignment. After the conversion use is spent, Alignment returns. No-legal-target behavior remains OPEN.
3. **Retrigger chance:** For a qualifying outside-category Specialization, add +5 percentage points before its four left-to-right card events, cap at 50%, and freeze `p` for all four. Each card has a first roll at `p`; after success, that **same card** may roll at `p × 0.5` and then `p × 0.5²`, stopping at the first miss or three extra hits on that card. Later cards still roll at the frozen `p`. If any card had a hit, reset the stored buildup after the hand; otherwise carry it forward. Each extra hit repeats only that card's Core synergy bonus portion, not its entire hand or card output. **Proposed arithmetic:** let `S_c` be the hand's raw total in Core category `c`, and `s_ic` card `i`'s raw contribution. After `h_i` extra hits on each card, award `roundi(1.5 × S_c + 0.5 × Σ(h_i × s_ic))` in each category. This preserves today's result when every `h_i=0` and rounds once per category. Exact rounding/integer representation and RNG receipt are implementation design. Four independent 5% rolls give about **18.5%** chance of at least one first hit in a hand; at the 50% cap they give **93.75%**, before chains. Those are arithmetic consequences, not balance approval.
4. **Rival standard:** Current Market pressure ignores a Studio's own releases when computing its targets, uses a limited recent-release window, and validates only a bounded lift above Genre base. This new **player-earned, rival-only, cumulative +2 rule capped at +8 specialist lift** adds to the current density/benchmark result, so a separate durable Genre/category record and a versioned target/schema rule are needed. “Every future game” implies the earned lift persists rather than using the recent-release window; exact save migration and rival-target validation remain implementation design. The player's old and active project targets must remain unchanged, while rival projects freeze their target when they Begin.

## Dependencies and questions for the next pass

- Confirm exact hand-event identity and post-enrollment rules for the selected four/four, two/two and three/three release-gated challenges in the sequential ladder. Tuition and completion raises are selected trial terms; hire path and first payday remain OPEN.
- Apply the selected highest-final-Core dominance test on training and post-training releases; add the capped specialist lift on top of existing Market pressure with explicit rival-only saved identity.
- Set exact arm/use timing and no-target behavior. Convert takes priority over Production Alignment while armed, then Alignment returns. Pass Conversion's target is selected from eligible owned Features; multiple selected cards should retain ordinary redraw unless the user chooses otherwise.
- Define deterministic roll order and combined rounding when several specialists independently respond to the same outside-category hand. The +5-point step, 50% cap, half-chance chain, three-hit-per-card limit and carry across games are selected trial rules.
- Coordinate the cumulative rival-only standard with the separate AI/Market design authority before implementation. Verify that a finite target range and checkpoint schema can represent it; no current source behavior is claimed here.

**Feasibility check, not a balance result:** `card_ledger.json` plus `feature_store_ledger.json` currently define 11 Graphics, 13 Sound, 14 Technology and 16 Design Features across Design+Alpha. Two pure-Feature hands in one game need eight distinct same-primary Features because Features are finite. Catalog-wide counts allow that, but owned, phase-eligible, affordable and nonreplaced supply may be much smaller. The challenge is therefore a later progression goal; implementation review must prove a legal route in each category before adopting it.
