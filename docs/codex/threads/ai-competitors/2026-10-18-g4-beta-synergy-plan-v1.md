## Hypothesis and candidate rule

H3: on the same two Design, two Alpha and two Beta hands, selecting useful QA category synergies from the seven visible Beta candidates can clear more Bugs and improve Review without changing legal card mechanics, draws, priorities, project length or Core selection. Review, not sales, is the primary endpoint. Marketing specialization is counted as an available synergy but is not treated as a Review gain.

The candidate enumerates the 35 four-card sets. A proposed set must be legal by visible finite-card identity and be either four QA cards with at least one Search and one Debug, or a 2/1/1 QA/Marketing/Insider Balanced Operations set with one Search and one Debug. It calculates the exact Beta Search, then Debug request arithmetic for each hypothetical hidden-Bug count from 0 through current required Scope, holding the visible known-Bug count fixed. A candidate may replace the current token-first hand only if it leaves no more Bugs for every hypothetical count and fewer for at least one. Among such sets, maximize summed Bugs removed across that range; then prefer greater Marketing output, Insider payout and stable token order. This is a conservative visible-information **TRIAL** policy: the hypothetical range is an analysis bound, not an AI view of hidden Bugs or an approved belief distribution. Log all-QA, all-Marketing, Balanced Operations, cost/payout and chosen opportunities. Beta commands remain subject to the game resolver.
