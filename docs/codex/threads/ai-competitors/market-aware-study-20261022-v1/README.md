## Required inputs and commands

First create and run the unchanged current-source baseline simulator variant and its private candidate fork, as directed by the study plan. Use `tools/simulate.py run --variant ...` to produce **one successful, frozen bundle for each arm**. Those ordinary simulator cases check legal single-Studio behavior but do not advance `RivalWorld`. Read the root `source_identity` from any bundle `cases/<id>/result.json` (not the nested policy identity). `run_world.py` checks that every case in its bundle declares that same identity.

From the repository root, substitute the exact paths and identities from the new bundles. Use a **new** output child under this thread's `sims/` for each record or replay:

```powershell
python docs/codex/threads/ai-competitors/market-aware-study-20261022-v1/run_world.py --bundle docs/codex/threads/ai-competitors/sims/<baseline-bundle> --output docs/codex/threads/ai-competitors/sims/<baseline-action-4417-output> --godot <Godot-console.exe> --source <baseline-gameplay-source-identity> --route action-war --seed 4417 --candidate 0
python docs/codex/threads/ai-competitors/market-aware-study-20261022-v1/run_world.py --bundle docs/codex/threads/ai-competitors/sims/<candidate-bundle> --output docs/codex/threads/ai-competitors/sims/<candidate-action-4417-output> --godot <Godot-console.exe> --source <candidate-gameplay-source-identity> --route action-war --seed 4417 --candidate 1
python docs/codex/threads/ai-competitors/market-aware-study-20261022-v1/run_world.py --bundle docs/codex/threads/ai-competitors/sims/<candidate-bundle> --output docs/codex/threads/ai-competitors/sims/<candidate-action-4417-replay-output> --godot <Godot-console.exe> --source <candidate-gameplay-source-identity> --route action-war --seed 4417 --candidate 1 --replay-input docs/codex/threads/ai-competitors/sims/<candidate-action-4417-output>/world-report.json.tape.json

python docs/codex/threads/ai-competitors/market-aware-study-20261022-v1/compare_worlds.py --baseline docs/codex/threads/ai-competitors/sims/<baseline-action-4417-output>/world-report.json --candidate docs/codex/threads/ai-competitors/sims/<candidate-action-4417-output>/world-report.json
```

Repeat only for Action/War seed 4418, Puzzle/War seed 4417 and strong Action seed 4417. Baseline and candidate use **the same recipe IDs and seed** per route. Action/Puzzle use the retained ordinary two-hand six-release player policy. Strong uses the accepted legal Family Funding/Graduate two-release route, including its existing first-project 5/11/3 player-hand schedule and base-target `_assess` call. **Candidate helper changes must preserve that base-target player call**; target-aware scoring is only for rival choice. Rival hand counts remain 2/2/2.

Each world record/replay has a hard 240-second Godot process timeout; the separate import also has a 240-second timeout. Ordinary worlds stop after six player releases, 180 player commands or 48 productive cycles; strong stops after two releases, 180 commands or 36 cycles. The harness retains illegal action and invariant failures rather than silently continuing. `run_world.py` rejects undeclared route/seed pairs, a mismatched source identity, a non-simulator bundle, old output paths or a tape outside this thread's `sims/`.

## Evidence and comparison boundary

- `world-run.json`, `world.command.json`, `world.log` pin the bundle manifest, script/runner/Godot hashes, exact command, process exit, wall and actual Godot CPU seconds, parse errors and timeouts.
- `world-report.json` records initial state/RNG, checks, every rival policy observation and selected token set, per-cycle resolved Core/Scope/Bugs/cash/outstanding bills, player release targets and sales, every actual rival publication, policy/world wall timing, checkpoint bytes and memory diagnostics.
- `world-report.json.tape.json` is the lossless interleaved command/result/state/RNG record. A fresh replay compares each player command, rival policy choice signature, result, world advance and full state digest; elapsed policy times are deliberately excluded from exact comparison.
- `world-report.json.checkpoint.json` is the latest completed Studio player/world pair captured by the harness. The source-matched `--restore-input` run hydrates that pair in a separate Godot process and checks recaptured payload, world observation, calendar, player RNG and release history. Do not load this checkpoint across arms or source revisions.
- `compare_worlds.py` reads paired reports without writing files. It checks legal initial digest and typed RNG parity, names the first divergent aligned rival hand, and summarizes rival Reviews, Core deficits, release cycles, cash, player exposure, CPU and checkpoint size. `BLOCKED` means interpret neither arm as an equal-start comparison.

Compare the initial full state digest **and typed RNG snapshots** before any policy outcome. Source identities differ across variants by design, so do not feed one arm's checkpoint or tape into the other and do not claim ordinary same-version `compare_simulations.py` parity. Normalize away only the known source identity and transient observation additions when auditing baseline-versus-candidate controls. Puzzle/War should retain identical gameplay actions and outcomes when both rivals' frozen standards equal Genre base. Record any divergence or absence of changed choices; do not replace seeds, increase bounds or infer challenge from a passing run.

The retained executions are linked from the finding. This tooling changes no canonical gameplay and never commits or pushes.
