# G4 synergy draw-priority follow-up — predeclared study, 2026-10-18

**Status: DESIGN experiment.** The first bounded [selection study](2026-10-18-g4-synergy-choice-plan-v1.md) changed only 2 of 32 Design/Alpha hands despite 18 affordable synergy opportunities. First Reviews improved in two of eight routes and tied six; Puzzle/4417's second Review fell from 2.2 to 2.0. That policy is not an adoption choice. The follow-up asks whether *legal pre-deal priorities* can make stronger synergy hands available without adding hands.

## Hypothesis and rules under test

H2: at Studio project start and before Alpha's first deal, a deterministic primary-Core focus based on currently owned Primitive Features and the project's relative Genre Core shortfalls will increase useful specialization opportunities and first/second Reviews over both the existing Feature-first policy and the selection-only v3 candidate. The same legal four-card selection, two hands per phase, Beta choice, first-project Genre/Theme, finance and exit rules remain unchanged. No Store purchase, redraw, Bank, hidden state or future RNG is used.

Fork `g4-synergy-20261018-v4` from the private v3 variant. Only its `project/` copy changes: the trial policy may request a valid 100-point Design distribution before the first deal and a valid Alpha distribution before its first deal. The target primary Core gets 50; remaining categories get 20/15/15 in descending relative Genre shortfall order, stable Core order for ties. Choose the target by greatest count of owned, project-eligible Primitive Features with that primary label in that phase; require at least three such Features so one matching Pass could complete a four-card specialization, then break ties by current relative Genre shortfall and fixed Core order. If no valid target or the intended distribution is already set, begin normally. The v4 test wrapper retains `reference` and `synergy` no-priority controls within the same source revision; verify those against v3 outcomes before interpreting `synergy_focus`. This Primitive roster focus is a candidate, not a final G2 Store/owned-pool planner.

## Cases, bounds and measurements

Use the same eight January recipes, seeds, traits, Genres, Fantasy Theme and 45-command/one-release/240-second bounds as v3. Compare three modes per recipe: original Feature-first, v3 synergy selection without priorities, and v4 synergy selection with priorities (24 cases). Keep all first-release starting recipes matched on full state/RNG; no old checkpoint crosses revisions. Continue Adventure/4417 and Puzzle/4417 from each mode's own v4 Studio checkpoint to an absolute second release with at most 45 further commands and the same process timeout (six cases). Replay one focus first release from each of those Genres and one focus second release in fresh processes.

Record priority commands/validation, every visible Design/Alpha synergy opportunity and chosen combo, exact committed Core/Scope/Bugs, Reviews, release cycle, cash low/arrears, earned/settled sales and Fans, accepted/rejected commands, policy/observation time, source identities and save/RNG parity. Compare v4 controls with their v3 counterparts on actions and outcomes. A changed deal changes the future RNG path; identical seeds only establish matched initial states, not matched later candidates. Keep Beta unchanged. Retain any rejected, timed-out or incomplete route and reduce reproducible action/invariant failures.

If the priority arm fails legal validation, no first release, replay or control parity, stop the promotion claim. If it gains combos but not Reviews, or harms second-game Review/cash, retain it as a diagnostic and keep draw/hand policy OPEN. Passing these first and second releases would justify a real incumbent-world follow-up, not automatically approve rollout, extra hands, population CPU or market coefficients.
