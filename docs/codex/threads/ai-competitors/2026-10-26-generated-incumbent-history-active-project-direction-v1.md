## Reconcile with the frozen-history lock

1. **Historical visibility, frozen accounting.** Keep each pre-1980 title in the [locked typed archive](2026-10-09-incumbent-history-decision-v1.md), with stable Studio/title identity, dated Genre, Theme and frozen Review. Expose these titles in a clearly labeled historical area of Market alongside chronological context. They do not enter `released_games`, the live release index, 1980 ranking, following-month news, recent Genre/Theme sales crowding or post-start sales/Fans. The current [Market browser](../../../patch-notes/scripts/ui/market_browser.gd) explicitly excludes the archive, so this requires a separate presentation/query change; do not silently treat archive rows as active sales titles.
2. **Credible trajectory.** Generate or select a versioned, per-save history recipe whose early titles are visibly weaker and whose late-1970s titles include the desired 8.x–9.x reputation. Preserve variation in Genre, Theme, date and Review rather than using identical score ladders for every Studio. The qualitative earlier-low/later-high arc is selected; exact title counts, years, Reviews, Core vectors, per-title sales history and allowed variation remain **OPEN**. If a recent historical title is proposed as an opening Review benchmark, it needs dated four-Core provenance and a separate benchmark rule. Its high Review alone is not Core evidence.
3. **A real January project in progress.** Each generated rival starts at the January 1980 shared boundary with a distinct active project identity, chosen Genre/Theme, phase, already committed Scope/Core/Bugs, remaining eligible Feature supply, legal hand/draw state and a coherent cash/runway snapshot. Its January state represents pre-start work, not a cycle-zero release or free January actions. From the first player cycle onward, the AI uses ordinary legal Design/Alpha/Beta hands, must complete actual Scope, prioritizes useful public Search→Debug before affordable Marketing, and receives its final Review from the shared calculator. A partial starting project is not an assigned 8.0 outcome.
4. **Freeze the project when it began.** Keep the active project's Genre, Theme and four Review standards frozen at its original pre-1980 begin point, with a versioned source/provenance record. Do not recompute targets from a January benchmark or player/rival releases after work has already begun. The opening benchmark, if adopted, applies only to projects legally begun after its effective date. Exact pre-start date/phase and historical market-standard recipe remain **OPEN**.
5. **Generate once, then persist.** Derive cohort/history/project selection deterministically from the new-save seed and a versioned generator recipe; materialize the resulting Studios, archives, active projects, hand/RNG and opening resource snapshots in the first world checkpoint. Continue restores those exact values instead of regenerating or reselecting a favorable opening. Existing saves retain their current cohort and project state unless a named, validated migration is separately approved.

## Provenance recommendation and alternatives

For the January active project, use a finite, source-pinned pre-start legal hand tape or equivalent validated project-state recipe prepared offline. It should account for committed Features, phase legality, Scope/Core/Bugs, costs and time before January, then produce a checkpoint-valid state with no post-start transaction replay. This avoids years of hidden runtime simulation during save creation while making the partly finished project auditable. The exact prelude representation, validation and compatibility with the current nonnegative `RunState` cycle model are **OPEN**; a prototype must prove this rather than editing a few project fields directly.

| Alternative | Disposition |
| --- | --- |
| Put old titles in the live release ledger so they appear in Market. | Rejected by the frozen-history lock: it fabricates January sales age, Fans and settlement, and would count old games as fresh saturation. |
| Generate an 8.0 Review or completed Scope directly for the active project. | Rejected: the first new game must resolve actual legal work and ordinary scoring. |

| Begin every rival from an empty January Studio. | Current ACTIVE/TRIAL behavior; it does not show work already underway and delays the stronger live opening. |
