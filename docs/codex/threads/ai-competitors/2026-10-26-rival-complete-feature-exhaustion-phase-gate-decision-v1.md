# Rival complete Feature exhaustion before phase progression — 2026-10-26

**Status: LOCKED qualitative design rule; not implemented.** The user directed that rivals **must exhaust all possible Features before progressing phases**. This extends the [October 24 visible-deal rule](2026-10-24-feature-exhaustion-exit-decision-v1.md): finishing only the currently visible Features is no longer enough if another phase-eligible Feature remains in the project's finite supply. It works alongside the separate [HARD LOCKED full-Scope gate](2026-10-26-rival-full-scope-hard-release-gate-decision-v1.md). The player's phase rules are unchanged.

## Phase gate

1. At each Design and Alpha phase exit, inspect the project's **frozen, unplayed, phase-eligible Feature supply**, including Features not in the visible candidate deal. A Feature is *possible* only if it can be selected through ordinary legal draw/hand rules and committed in an affordable four-card hand under the current project, prerequisites and cash. Do not count future Store purchases, ineligible-phase cards, already committed Features or renewable Passes as remaining Features.
2. While any possible Feature remains, the rival must continue legal Feature play. Within each visible deal, retain the maximum legal, affordable Feature count per hand; after refill, reassess. When the visible deal has no playable Feature but the finite supply does, use ordinary legal redraw or funded productive hands to surface that supply. No hidden next draw, injected card, free redraw, fabricated cash or bypass of hand validation is permitted.
3. Design may progress only when **no possible Design Feature remains**. Alpha may progress only when **no possible Alpha Feature remains** *and* committed played Scope meets the frozen required Scope. If Feature work becomes impossible because of legality or funds, record the reason and use only an ordinary legal recovery. An Alpha project below Scope stays blocked and unreleased. Feature exhaustion does not waive the Scope gate; meeting Scope does not waive Feature exhaustion.
4. This is a finite-Feature objective, not an obligation to play unlimited Pass hands or wait indefinitely for future income. The exact draw-search method, affordability reserve, proof that remaining supply is unreachable, termination bound, distressed-project recovery and save migration are **OPEN**. An implementation must avoid both a premature phase exit and an unbounded search; it must never solve that tension with a synthetic release or Scope grant.
5. Beta has no Design/Alpha Feature supply. Its funded Search→Debug and Marketing policy remains separate and **OPEN** in detail. Exhausting Features may improve Scope/Core, but extra cycles and Bug pressure can offset Review gains; no Review score or publication cadence is guaranteed by this ruling.

## Runtime mismatch and test boundary

Current `RivalTrial._feature_maximal_choice` searches legal four-card combinations only among **visible** candidates, then requests phase exit when none can be played. It does not audit remaining phase-eligible finite supply. The [existing forced-Feature comparison](2026-10-24-forced-feature-finding-v1.md) tests visible exhaustion only; its Review and release-density results do not establish the impact of this stronger gate.

Before a source-pinned adoption handoff, compare current behavior with whole-supply exhaustion on matched legal starts. Include a hidden-but-drawable Feature, true empty supply, unaffordable/ineligible remaining Features, Scope met before exhaustion, exhausted Alpha below Scope, short-cash recovery, save/Continue and fresh-process replay. Measure Feature counts, Scope/Core, Bugs, cash/dues, Review, rival publication timing/count, player market pressure and CPU. Existing first-game supply deficits must be addressed through legal Studio admission or recovery before claiming this gate is viable. No canonical gameplay change follows from this design record.
