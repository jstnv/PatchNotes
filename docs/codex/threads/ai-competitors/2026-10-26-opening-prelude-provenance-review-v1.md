# Opening rival provenance contract — design review, 2026-10-26

**Recommendation: a one-time, versioned January bootstrap with two separate inputs. Status: DESIGN/OPEN.** The first input is a dated, frozen prior-career archive for historical Market display and an explicitly authored opening resource snapshot. The second is a short *legal* late-1979 development tape for each rival's active project. On new-save creation, validate both, translate the paid prelude's ending state into a January cycle-zero opening state, and save the resulting shared world once. Normal gameplay then advances without per-rival calendar offsets.

This is a design contract, **not** a claim that the current runtime can already perform the translation. The [headless gate](2026-10-26-prestart-normalization-gate-finding-v1.md) shows that current active-rival Studio checkpoints reject a cycle rewind even when finance `last_cycle` is changed with it. The [timing study](2026-10-26-prestart-shadow-timing-finding-v1.md) shows the potential 1–4-cycle wait after a six-cycle prelude, but did not create a January save. The [history prototype](2026-10-26-opening-history-headless-finding-v1.md) shows a separate display query with three 8.0+ trial archived titles, but not a generator or rendered screen.

## Required separation

| Record | May affect | Must never affect after Jan 1980 |
| --- | --- | --- |
| Frozen pre-1980 titles | Historical Market view and an explicitly labeled all-time comparison | Live release ledger, monthly earned sales, Fans, saturation, following-month news, 1980-only rankings |
| Authored incumbent opening resources | January cash, Fans, owned Feature pool, specialty/traits, liabilities, with a typed origin | Retroactive post-start payouts or silently granted unowned Feature hands |
| Legal late-1979 prelude | Active project phase/hand/Scope/Core/Bugs, spent cash, dues, RNG, frozen targets | A free hand, score floor, direct Scope/Review assignment or shifted live player calendar |
| New 1980 releases | Ordinary Market standards, sales, Fans, current rankings and news under normal rules | A fabricated archived 8.0+ result |

The user's now-accepted **5.6–6.2** ordinary first-live quality and desired **8.0+** visible prior titles are distinct tests. Archived 1979 ratings cannot establish a first-place **1980 releases** challenge. The latter is an independent OPEN design target.

## Bootstrap shape for a private candidate

1. **Author and version a cohort recipe.** It names each studio, genre specialty, traits, dated title archive, explicitly justified prelude-start cash/Fans/owned Features, and a deterministic seed derivation. Archive Review values are record data, not outputs of a simulated current-rule game. The trial seven-title history/three 8.0+ screen is not yet approved production content. At least one lower-rated earlier title per established rival should remain visible so the high scores do not look like first games.
2. **Execute a bounded legal prelude in a scratch world.** All project starts, deals, owned-Feature checks, Design/Alpha/Beta hands, monthly rent/payroll/debt, and random draws pass through the actual command path. The scratch clock must have an explicit late-1979 origin and month alignment; labeling the current `RunState` cycle 0 as October 1979 without changing its calendar authority would be false. Record the command tape, source/content identities, starting snapshot, final checkpoint, and each paid boundary. Reject blocked or unaffordable routes instead of finishing a project by field edits.
3. **Convert at the January boundary through a new typed schema.** The conversion proves the prelude and maps its ending cash, Fans, ownership, liabilities, active project, Feature supply, hand tokens, project serial, priority/QA state and RNG to the new world at cycle zero. The live Studio finance ledger needs a documented January opening-balance receipt or equivalent validated bridge; current `StudioCheckpoint` assumes original 550,000-cent funding and a journal beginning at cycle zero. A reset of `completed_run_cycles` alone or together with `finance.last_cycle` has been experimentally rejected. Prelude receipts must remain inspectable as provenance outside live post-start monthly revenue.
4. **Freeze prelude-era project targets explicitly.** Current `BeginProject` takes a market snapshot at the actual Begin transaction, and the rival checkpoint validates that frozen target and its source against monthly Market history. A pre-1980 project needs an authenticated target origin that the live validator can distinguish from Jan 1980 and from old neutral-save migration. Do not quietly refreeze its targets at the player join or insert archived titles into active saturation to make them reconstructible.
5. **Validate and save exactly once.** A new world schema should reject changed prelude tapes, cash/Fans/Feature/hand/market/RNG payloads, duplicate project/history IDs, and a mismatched source or calendar origin. Cold Continue must retain the active project and first post-start legal hand exactly. Old saves should continue without a retroactive WIP generator or changed historical records unless an explicit migration is separately approved.

## CPU and scope choice

Prefer a **bounded cohort recipe plus short per-save legal prelude** for the first candidate. Existing rival seeds depend on the newly created player's run ID, so a raw precomputed state cannot simply be copied into arbitrary saves without typed ID/RNG remapping and fresh validation. If per-save work becomes too expensive, test a parameterized, source-pinned prebuilt template after the lawful path exists. Count both initial construction and every save/load validation cost; a one-time generation spike can matter to player experience. Do not widen the live rival population until the WIP bootstrap's CPU, save size and publication density are measured with actual legal releases.

## Private candidate acceptance before any handoff

- Two fixed seeds and independent repeat; baseline, history-only, WIP-only and combined arms with starting-state/source differences disclosed. At least two incumbents; several visible 8.0+ historical games; early weaker history; zero active Market facts/sales/Fans from archives at creation.
- Multiple genuine prelude lengths/phases and at least one actual **post-start** release by cycle 12. Report all Review values, Scope required/played, known/hidden Bug limits, cash/rent, remaining Feature supply and timing; no Review floor or under-Scope shortcut. If the current trial policy remains at 2.4–4.7, improve the quality policy separately before claiming the user's accepted ordinary range.
- Source-pinned tape replay; exact state/RNG determinism; reject bad cash, wrong cycle, missing Feature, altered hand token, duplicate archived ID and changed project target; first post-start hand accepted; checkpoint capture/restore and cold Continue produce the same next action and release; old-save regression remains valid.
- Bound construction and save/load CPU, memory, file size, zero-step hand search and 24-cycle release density. Retain failures/timeouts. No coefficient, 35-Scope pool, thousands-Fans start or 8.0+ archive count becomes ACTIVE/TRIAL just because an isolated candidate passes.

Current canonical edits are concurrent, and the frozen diagnostic variants predate them. An implementation review must first reconcile its exact source identities with the newer runtime. A proposal for the internal TODO needs a tested candidate and a versioned adoption handoff; neither exists for this bootstrap yet.
