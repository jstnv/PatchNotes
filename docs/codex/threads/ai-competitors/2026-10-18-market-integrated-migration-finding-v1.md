## What the v26 candidate actually checks

- [Frozen old schema](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/market/legacy_pre_market_schema.gd), [old sale math](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/market/legacy_pre_market_sales.gd), and [old Fanbase replay](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/market/legacy_pre_market_fanbase.gd) were copied from the `f8f130…` old-source candidate into the private project. Class references were relocated; the old sale math and neutral shadow accounting did not change. [Preflight](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/market/legacy_pre_market_studio_validator.gd) requires the exact old encoded Studio field count/kind, source build, RNG algorithm and expected content revision, decodes the old root schema, checks run identity, and validates each old real sale plus the full old Fanbase ledger. This runs on raw player/rival payloads **before** `_upgrade_sales`.
- [Migration adapter](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/market/market_save_migration_trial.gd) maps four known world IDs to old revision `dd095178754c57e1f7eba29959c26e5cb023e81b3074b238b6af7655019f455e` and `067972…`/`3e0d…` to `e5fa9d0bf6ac3f0722f2b310e0a14c0de07a8c4b4deccce9b703894406eae1ea`. The worldless normal Store route recognizes only the exact `dd095…` revision and strict old shape; it does not invent a gameplay source ID absent on disk. Historical real sales receive 10000-bp factors tagged with the actual old world source (or old f8 source for worldless); neutral Fanbase shadows use `market-0-neutral`. Migrated *copies* of player/rivals get the new `sales2` revision `614b28a6efda461c850196b162c5f60b299eb3829f72755f660773b2a30f7c8d`, then pass current Studio and world validation.
- [Coordinator](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/persistence/checkpoint_coordinator.gd) applies one in-memory conversion for Store validation and the same conversion for Continue hydration. Known-old malformed data is `invalid`; unknown revision/source is `incompatible`. Old Store generations remain byte-identical until a later legal Studio action publishes a new generation. The only game rules change relative to v23 is the [Studio rules revision](simulators/market-migration-integrated-20261018-v26-verifier/project/scripts/persistence/studio_checkpoint.gd) `sales1→sales2`; the market factor remains trial data.
