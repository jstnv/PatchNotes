## Selected rule

1. A two-parent Feature requires permanent ownership of **both distinct named parents** before zero-cycle research admission. Queue membership is not ownership. Every missing parent is visible; no ancestor is automatically bought, deposited or queued when the child is inspected.
2. Eligible committed play contributes one familiarity credit per parent ID per project. Sum both parent credit counts, then apply the existing 10% per credit with **one shared 50% cap**. Two different parents may each credit in the same project. Ownership, draw, selection, repeated same-ID play within one project and Contract use do not credit. Existing single-parent and special Gameplay-owned-count rules retain their behavior.
3. The child's admission down payment remains half **base** price, with zero cycle cost and no familiarity discount. Its current/future Research installments recompute the combined discount when each action occurs. Earlier payments stay fixed. Current one-action live durations remain unchanged; future-node durations are OPEN.
4. The conditional acquisition path includes all required parents and each distinct shared ancestor once. UI detail identifies every parent, each credit contribution, the combined cap, all missing gates and the current down/next-installment quote. A child may retain one layout anchor, with other required parents shown explicitly as AND requirements; a visually duplicated node or hidden cross-lane gate is not acceptable. The transaction quote stays authoritative.
5. Reject duplicate, missing, self or cyclic parent references before using a candidate graph. Do not infer named parents from lanes or platform tags. No hybrid named-parent-plus-Gameplay-count node is authorized by this ruling. Sub-Areas retains its separately selected independent access.
