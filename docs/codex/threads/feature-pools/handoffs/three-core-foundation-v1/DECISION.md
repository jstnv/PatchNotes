## Selected capability

1. A new Design/Alpha Feature definition may supply an **ordered sequence of one to three Core contributions**. Each entry has one of Graphics, Sound, Technology or Design and a positive integer value. Entry 0 remains the sole primary contribution. Preserve authored order; do not sort by value or merge duplicate category entries. Reject a new ordered definition with duplicate categories, zero/negative/nonintegral values, missing intermediate entries, more than three entries or ambiguous simultaneous legacy production fields. Existing one-/two-Core definitions retain their current accepted input and behavior.
2. One validated accessor exposes the ordered contributions to consumers. Legacy primary/secondary fields remain a compatibility input or projection until every current consumer is migrated; there must be no consumer that silently drops the third entry. This is a structural implementation choice, not a new card.
3. Draw weight is the sum of `priority[category] × printed_value` over all entries. Production adds every printed value to its category exactly once and counts Scope once. Specialization still matches only the first entry, then applies the existing one-time multiplier and rounding to aggregated category totals. Balanced Production uses those totals and its current redistribution/remainder order. Design/Alpha Bug Pressure uses the sum of raw printed values times Scope divided by the existing phase denominator, retaining downstream finalization.
4. A three-Core test fixture must render all three ordered scores in the card and relevant Store/hand summaries. Primary color and specialization explanation stay tied to entry 0. Test fixtures may exercise this capability; no authored card enters the live Store, Primitive roster, Contract pool or project supply through this handoff.
5. Existing Employee matching and historical training events are unchanged. Whether a third category later matches a Specialist is **OPEN** with the Employees system; a future live three-Core card needs that cross-system ruling and any event migration. Contract eligibility for later Store Features also remains **OPEN**. No save identity is rewritten to force old checkpoints across changed source rules.
