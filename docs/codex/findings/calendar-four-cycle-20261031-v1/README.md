## Contract and architecture

`calendar_clock.gd` is the sole active cycle/calendar arithmetic authority. Fresh Studios use four productive actions/month and48/year. Run/project/hand/review/event cycle counters remain raw action counts. Passive commands consume no time. Clock labels use month-of-year and Week1–4; absolute finance month IDs remain separate. The old `get_current_half` query still returns first/second half.

A missing/empty clock profile explicitly means historical two-cycle timing. Fresh profiles are `{version:2,legacy_until:0}`. Existing valid saves convert after provenance validation at raw cycleC: calendar quarter coordinate is2*k throughC, then2*C+(k-C). Thus an old cycle9 Month5 Second Half becomes Week3 at unchanged raw9; future raw10 is Week4 and raw11 starts Month6. Old dates, cents, records, RNG, actions and issued bills never rescale. Only unissued future recurring dues map to their original calendar dates. Finance also saves an action-index cutover to distinguish old and new zero-cycle operations at the sameC. Loan/education/payroll schedules retain immutable issuing contexts. Sales retains raw earning counts plus release-age/run clock contexts, preserving old partial halves and cumulative rounding. Fanbase and reports use the same clocks. Current saves use `studio-checkpoint-calendar-v2` and reject conflicting run/ledger/sales/world clock contexts.

Certified1977 history and raw72 owner offsets stay unchanged. Owner profiles shift by72; conversion happens after historical validation/closure. Existing Market v2/v3/v4 proofs keep their exact shape. Calendar-bearing v5 snapshots and new IDs allow odd cutovers. The existing twelve-old-cycle presence window remains six months, now24 fresh cycles. The initializer, provider, scheduler, snapshot and restored world check owner/player alignment. `ProjectState` recognizes the new validated Book proof prefix.

Action-count rules stay fixed: Design/Alpha/Beta hands, Pass Budget, exhaustion, Support6/24 earning-cycle windows and Contract2/3 hands.
