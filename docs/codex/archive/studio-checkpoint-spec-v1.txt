2. Player contract and exact checkpoint boundary
One automatic Continue slot. Initial named Studio is checkpointed after its $5,500, six free Features and existing redraw refill are committed. Each successful Studio purchase (including zero-cycle starter purchases), reserve purchase, later Store purchase and campaign saves after the COMPLETE authoritative transaction: cash, ownership, productive cycle, per-release earning, monthly settlement, redraw refill, unlocks and notifications. Closing/browsing a Store, selecting a node/summary, acknowledging a tooltip, canceling, failed purchases and unchanged/invalid actions do not write a checkpoint. Presentation acknowledgments may be included in the next real checkpoint; they may repeat after restart if not subsequently checkpointed.
Returned Studio after committed launch: checkpoint after immutable release registration, frozen Review/history, qualifying SideStreet entitlement and redraw refill. Launch remains zero-cycle. Returned Studio after completed Contract dismissal: checkpoint after the already-paid result/history and refill, never pay again while saving. If the process exits on a completed Contract's result screen BEFORE dismissal/return to Studio, Continue restores its pre-acceptance Studio checkpoint; the unsaved completion, upfront, hands, cash and sales are discarded together. That is the specified checkpoint policy, not a duplicate payout.
Pre-development / pre-Contract checkpoint means the last quiescent STUDIO state BEFORE accepting the departure action. Opening either modal is passive and does not save. At confirmed departure, verify the latest committed Studio state is durably checkpointed before consuming RNG, constructing a project, accepting an offer or awarding Ironclad's $400. Do not create a checkpoint containing the project's one-cycle start or an accepted unfinished Contract. The currently valid identical checkpoint need not be rewritten. If a pending prior Studio save failed, retry it and block departure until resolved. Restart mid-Design/Alpha/Beta/Review/Contract returns to Studio before that departure; no intermediate sales, spending, cycles, tutorial progression, familiarity or upfront survive. This resolves the queue's abbreviated 'pre-development/Contract checkpoint' consistently with §62's no active-phase resume.
On restore, display the saved year from completed_cycles, not wall clock; do not advance calendar, refill redraws, register releases, settle sales, trigger unlocks or reaccept Contracts as load side effects. A normal new/returned Studio checkpoint already has the correct refill. Continued Studio uses the stored bank exactly.

3. Exact persisted envelope and scalar encoding
Directory: user://saves/studio/ (settings live separately). The single logical slot is backed by current and prior committed generation files. Format identifier 'patch-notes-studio-checkpoint', schema_version '1'. Envelope exact fields: format, schema_version, payload_utf8, payload_sha256. payload_utf8 is one UTF-8 JSON object encoded as a JSON string; SHA-256 hashes the decoded payload string's UTF-8 bytes. This avoids reserialization/key-order hash ambiguity. Checksum detects damage, not malicious editing; no security/anti-cheat claim.
All integral state, including cash cents, cycles, sequence, score/count fields, signed RNG state/seed, schema version and array integer entries, uses canonical decimal STRINGS. Parse with checked signed64 conversion before constructing state; forbid fractional/exponent/whitespace/leading-plus/leading-zero variants except literal '0'; allow '-1' only in explicitly sentinel-capable fields. Reject overflow without floating-point conversion. Negative signed RNG bit patterns are valid. Godot JSON number coercion must not round 64-bit cash or RNG state. IDs/text remain strings, flags booleans, absence null, containers arrays/objects. Existing float Review components use explicit {"f64":"16 lowercase hexadecimal IEEE754 bits"}, rejecting NaN/Infinity; preserve original finite bits instead of recomputing Review. Define typed adapters per field; never infer integer/float type from an arbitrary string.
Root payload exact fields: checkpoint_kind='studio', run_id (nonempty immutable generated run identity), sequence (monotone generation), source_build (diagnostic identity), content_revision (explicit compatible runtime-data/rules fingerprint), run, releases, contracts, publishers, guidance, rng. No executable objects, script paths, Variant/object deserialization, scene tree, Callable or signal reference.
Do not equate source_build to compatibility. Initial implementation writes one content_revision incorporating runtime card/Store/market definitions and result-rule versions; load accepts only declared compatible revisions. Harmless source edits need not invalidate saves, but unrecognized content/rule fingerprints must show incompatibility. A new compatible list entry requires tests. No pre-save legacy migration is promised. A future schema requires a separately reviewed mapping.

6. Transaction map and failure handling
Coordinator owns checkpoint publication; model signals such as cash_changed/calendar_changed are NOT save triggers because they can expose intermediate state. Hooks: successful named _enter_initial_studio; successful purchase_starter_feature/purchase_feature/purchase_primitive_reserve_feature/purchase_post_launch_campaign after return and guard cleanup while still Studio; successful _replace_beta_with_launch after registration/refill; successful _on_contract_completion_dismissed after refill. Pre-departure checks precede _begin_next_project preparation and Studio's accept_primitive_contract/accept_sidestreet_offer calls. Do not save only in _on_contract_requested: acceptance already awards upfront before that callback.
Capture detached full state on the main thread after all authoritative callbacks complete. Validate/hash serialized snapshot, write/flush/close, reopen and validate bytes, then atomically publish. Mark 'Saved' only after successful publication. A gameplay success followed by I/O failure remains one committed in-memory action: show 'Not saved — Retry / Return to last saved Studio / Quit without saving'. Disable further mutating/departure actions until resolved; allow passive inspection. Retry writes the same current snapshot, not the action again. Explicit Return replaces the ENTIRE run with the last checkpoint; explicit Quit warns of loss. Do not silently roll cash backward while keeping purchase/phase side effects. A failed GAMEPLAY action does not save or alter bytes at all.
Atomic generation protocol: one logical slot, physical checkpoint.<monotone-sequence>.json files. Write a uniquely named .tmp in the SAME directory, validate it, then rename to a never-existing final generation name using a platform-tested same-filesystem atomic rename. Publish filename is the commit point. Never delete current first or rely on overwrite-rename semantics. Highest finalized generation is the current candidate; its preceding validated committed generation is the backup. Retain at least those two until newer publication succeeds. Clean only older validated generations after commit; preserve any corrupt/incompatible evidence. .tmp files are not auto-promoted; crash before rename uses previous checkpoint, after rename uses new checkpoint. Filename sequence must equal payload sequence; duplicate generations or overflow reject writes. Enforce one process/writer for a slot or refuse the second writer. Full power-loss guarantees depend on tested filesystem durability; do not claim more than verified Windows crash-injection results.
Corrupt CURRENT: do not silently skip it and call the backup current. Show recovery choice with studio/version/cycle from a VALIDATED backup; explicit Recover uses that generation, preserves corrupt bytes, and publishes a fresh checkpoint only through an explicit recovery transaction. Both invalid -> clear error, Retry / Open save location / New Run confirmation; no partial play. INCOMPATIBLE highest generation -> show actual schema/content/engine version, preserve bytes, do not silently fall back or migrate. New Run provides explicit replacement warning and non-destructively archives existing generation files before initializing the replacement. If archive or new-save commit fails, previous data remains usable. Canceling name entry/New Run never replaces the slot. No separate manual playable slots; archived files are evidence, not a slot-selection UI.
