# Focused first-time system onboarding

Status: ACTIVE locally, 2026-11-02. Direct user request authorizes implementation and delegates missing conditions. This is presentation guidance, separate from passive Tips and scripted production practice. No balance or gameplay rules change.

| First-time condition | Invitation / optional tour |
| --- | --- |
| Signed bankroll below zero (cash minus all overdue obligations) | Bank: bills, actual quotes, payments and history |
| Three registered releases frozen to Public Action Engine | Engines: access, fixed libraries, royalties and separate ownership |
| First registered release | Contracts; Post Game Summaries; Daily Chart and Rival Info explanation |
| Two registered releases | Employees and training |
| A proprietary Feature-capable engine exists | Engine-specific Feature Implementation queue and future-game supply |
| A particular paid engine earns its next existing Skill challenge | That engine's Skill Tree |
| A publisher profile becomes accessible | Publisher browser and actual availability/terms |

These are subsystem invitations, not a popup for every acquired Feature card. Existing actual unlock gates remain authoritative; affordability is separate from access. Public release counting uses registered release-to-engine identities, never current selection or a royalty payment. Promotion is explained with summaries. The only current Public engine is Public Action.

Bank takes priority. Other invitations appear in Studio. Show at most one per immutable Studio ID + completed cycle + phase instance opportunity; remaining eligible systems wait for another opportunity. Do not stack unlock notices. Older saves can receive relevant invitations once. Hand presentation, loading, practice invitation, Awards, navigation, save warnings, pause, Settings, guides and other dialogs take precedence. Bank may be offered after resolved production/Contract hand presentation, never during it.

Every invitation has Show me around and Dismiss/Escape. Tours highlight existing controls using shared Onyx/Indigo/Mint FolderUI, Russo/Plex roles, Next/Back/Finish/Exit and animated appearance. Music and the normal time map continue; a tour consumes no productive cycle. Read-only Contracts and Employees previews return to their owning Studio group on exit so actions are not left in preview mode. Other existing menus remain usable. Tours do not accept, buy, implement, hire, choose an engine, pay, or draw RNG. Passive tip visitation is suspended during routing/tours so these do not alter checkpoint tutorial acknowledgments.

How to Play -> Start Here -> Guided system tours replays available tours, including from Pause. Refresh availability on every opening; keyboard focus scrolls into view. A delayed launch is fenced against phase/cycle/navigation changes and new modal owners. Intermediate navigation awaits are cancellation-fenced.

Acknowledgments are versioned local preferences in user://focused-guidance-v1.cfg keyed by immutable Studio ID. Mark when an invitation is actually shown, not while queued. Corrupt/unwritable preferences cannot block play; the session retains acknowledgments after an I/O failure. Debug automatic notices are suppressed, and manual Debug tours do not mark normal preferences. Copying a save to another device does not copy these local preferences. There are no new Run/DTO fields or tutorial autosaves. Ordinary Studio-only Continue is unchanged.
